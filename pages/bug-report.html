Bug Report Contoh 1: Critical

🔴 BUG-001: Login button tidak responsive pada mobile

Basic Information

  • Severity: 🔴 Critical
  • Priority: P1 - Top Priority
  • Status: Open
  • Assigned to: Dev Team Lead
  • Reported by: Pandu Wibisono
  • Date Reported: 2025-01-12

Environment

  • Device: iPhone 12
  • OS: iOS 17.2
  • Browser: Safari
  • App Version: 2.0.1
  • Build: Build 154

Steps to Reproduce

  1. Open the app on iPhone 12 with iOS 17.2
  2. Navigate to login page
  3. Enter valid credentials (email & password)
  4. Tap on the "Login" button

Actual Result

The login button does not respond to taps. No visual feedback is shown, and no API request is made. The user is stuck on the login page without any error message or loading indicator.

Expected Result

The login button should respond to taps with:

  • Visual feedback (button depression/highlight)
  • Loading spinner showing
  • API call to authenticate user
  • Redirect to dashboard upon successful login

Additional Details

Frequency: Always
Does it occur in other browsers/devices? Yes, also occurs in Android Chrome 120
Workaround: None identified

Attachments

📸 bug-001-screenshot.png
🎥 bug-001-video.mov
📋 error-console-log.txt

Bug Report Contoh 2: High Severity

🟠 BUG-002: Incorrect total price calculation with discount applied

Basic Information

  • Severity: 🟠 High
  • Priority: P1
  • Status: In Progress (Fix pending review)
  • Assigned to: Backend Team

Environment

  • Browser: Chrome 120
  • OS: Windows 11
  • API Version: v2.3.1
  • Database: Production

Steps to Reproduce

  1. Add product "Laptop" ($999.99) to cart
  2. Add product "Mouse" ($19.99) to cart
  3. Apply discount code "SAVE20" (20% off)
  4. Review cart and proceed to checkout

Actual Result

Cart Summary:
Subtotal: $1,019.98
Discount (20%): -$203.99
Total: $815.99 ❌ WRONG

Expected Result

Cart Summary:
Subtotal: $1,019.98
Discount (20%): -$203.996 ≈ -$204.00
Total: $815.98 ✓ CORRECT

Root Cause Analysis

The discount calculation is being applied to individual items and then summed, instead of applying to the total. This causes rounding errors.

Impact

  • Users are overcharged by $0.01 to $0.10 per transaction
  • Affects all discount code transactions
  • Potential revenue loss and customer complaints

Bug Report Contoh 3: Medium Severity

🟡 BUG-003: Search results pagination not working correctly

Basic Information

  • Severity: 🟡 Medium
  • Priority: P2
  • Status: New

Steps to Reproduce

  1. Go to Products page
  2. Search for "shirt"
  3. Results show 50 items per page
  4. Click on "Page 2" button

Actual Result

Page 2 button is highlighted as active, but the products shown are the same as Page 1. Pagination seems to be only visual without fetching new data.

Expected Result

Clicking page 2 should display items 51-100 of the search results. Pagination should properly fetch and display different sets of products.

Workaround

Users can use "Load More" button instead of pagination, which works correctly.

Best Practices untuk Bug Reporting

  • ✅ Be Specific: Jangan gunakan "tidak bekerja", jelaskan spesifiknya
  • ✅ Include Screenshots/Videos: Visual evidence sangat membantu
  • ✅ Provide Steps to Reproduce: Developer harus bisa mereproduksi bug
  • ✅ Include Environment Details: Browser, OS, app version, dll
  • ✅ Separate Issues: Satu bug report untuk satu issue saja
  • ✅ Use Clear Severity Levels: Jangan overstate atau understate severity
  • ✅ Check for Duplicates: Pastikan bug belum dilaporkan sebelumnya
  • ✅ Provide Expected vs Actual: Comparison membantu clarity
  • ✅ Add Attachments: Screenshots, logs, network traces
  • ✅ Follow Up: Komunikasi dengan dev untuk clarification jika perlu

Severity & Priority Levels

Severity Levels

  • 🔴 Critical: Application crash, security vulnerability, data loss
  • 🟠 High: Major functionality broken, significant user impact
  • 🟡 Medium: Feature not working as expected, limited user impact
  • 🟢 Low: Minor issues, cosmetic problems, typos
  • ⚪ Trivial: Suggestions for improvement, not a bug

Priority Levels

  • P0/P1: Must fix immediately, blocks release
  • P2: Should fix soon, affects user experience
  • P3: Nice to fix, minor impact
  • P4: Low priority, can wait
