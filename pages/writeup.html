Tulisan tentang cara berpikir dan pendekatan dalam testing

Beranda / Writeup Testing

Pendahuluan: Mindset Testing yang Benar

Testing bukanlah sekadar mencari bug, tetapi memastikan bahwa setiap fitur bekerja sesuai dengan ekspektasi pengguna dan bisnis. Dalam tulisan ini, saya akan membagikan pemikiran dan pendekatan saya dalam melakukan testing yang efektif dan bermakna.

Testing Mindset: Berpikir Seperti Pengguna

1. Shift-Left Testing

Jangan menunggu fitur selesai dikembangkan untuk mulai testing. Testing harus dimulai sejak fase requirement dan design. Dengan shift-left testing:

  • ✅ Cacat dapat diidentifikasi lebih awal
  • ✅ Biaya perbaikan lebih murah
  • ✅ Kualitas final product lebih baik
  • ✅ Time-to-market lebih cepat

2. Empathy-Driven Testing

Selalu bayangkan diri Anda sebagai pengguna akhir. Apa yang akan mereka lakukan? Apa yang akan membuat mereka frustrated?

  • Pikirkan tentang edge cases: "Apa yang bisa salah?"
  • Test dengan data nyata, tidak hanya happy path
  • Perhatikan user experience, bukan hanya functionality
  • Validate terhadap requirement bisnis

3. Risk-Based Testing

Tidak semua fitur memiliki risiko yang sama. Prioritaskan testing untuk area yang memiliki risiko tinggi:

  • 💰 Areas that affect revenue or transactions
  • 🔐 Security-sensitive features
  • 📊 Critical business logic
  • 👥 User-facing features dengan high usage

Strategi Testing: Test Pyramid

Test Pyramid adalah konsep yang menunjukkan proporsi ideal dari berbagai level testing:

E2E Tests (10%)
Integration Tests (30%)
Unit Tests (60%)

Unit Testing (Foundation)

Testing untuk individual functions atau methods. Ini adalah fondasi yang paling penting karena unit tests:

  • ⚡ Cepat dijalankan
  • 💰 Murah untuk maintenance
  • 🎯 Fokus pada logic
  • 🔧 Mudah di-debug

Integration Testing (Middle Layer)

Testing interaksi antara modules atau services. Memastikan components bekerja bersama dengan baik:

  • 🔗 Test API contracts
  • 💾 Test database interactions
  • 📡 Test service communications
  • 🔄 Test data flow

End-to-End Testing (Top Layer)

Testing complete user workflows dari start hingga end. Ini penting tapi harus dilakukan sparingly karena:

  • ⏱️ Slow to execute
  • 💸 Expensive to maintain
  • 🎭 Flaky (dapat fail for unrelated reasons)
  • 🧠 Complex to debug

Pendekatan Praktis: SAST Framework

Ketika testing sebuah fitur baru, saya menggunakan SAST framework:

S - Scenario (Scenarios)

Identifikasi berbagai skenario yang mungkin terjadi: 

Feature: User Registration
  Scenario 1: Register dengan email valid dan password sesuai requirements
  Scenario 2: Register dengan email yang sudah terdaftar
  Scenario 3: Register dengan password yang tidak sesuai requirements
  Scenario 4: Register dengan field yang kosong
  Scenario 5: Register dengan email format invalid

A - Actions (Tindakan)

Tentukan tindakan yang akan diambil user untuk setiap scenario: 

Scenario 2 (Duplicate Email):
  1. Fill email: existing@email.com
  2. Fill password: ValidPass123!
  3. Click Register button
  4. Observe system response

S - States (Status)

Check status application setelah setiap action: 

After Action 3:
  - Error message displayed: "Email already registered"
  - Form is still visible
  - User remains on registration page
  - No account created

T - Testing (Test Execution)

Execute test dan dokumentasikan hasil: 

Test Result: FAILED ❌
  Expected: Error message "Email already registered"
  Actual: No response, infinite loading spinner
  
Severity: Critical
Recommendation: Investigate API validation logic

Common Testing Mistakes (dan Cara Menghindarinya)

1. ❌ Hanya Test Happy Path

Problem: Hanya test "normal" scenario akan membuat bugs slip through.

Solution: Always test negative scenarios dan edge cases:

  • Empty inputs
  • Invalid data formats
  • Boundary values
  • Error conditions
  • Concurrent operations

2. ❌ Testing Without Requirements

Problem: Tidak tahu apa yang seharusnya di-test tanpa clear requirements.

Solution: Pastikan requirements jelas sebelum testing:

  • Clarify ambiguous requirements dengan product owner
  • Document expected behavior secara explicit
  • Create traceability matrix (RTM)
  • Involve stakeholders dalam requirement review

3. ❌ Manual Testing Everything

Problem: Manual testing tidak scalable dan error-prone.

Solution: Automate repetitive tests:

  • Identify repetitive test cases
  • Create automation framework
  • Keep automation maintainable
  • Reserve manual testing untuk exploratory dan complex scenarios

4. ❌ Poor Test Data Management

Problem: Test data yang buruk menyebabkan unreliable tests.

Solution: Implement proper test data strategy:

  • Use realistic data
  • Create data cleanup procedures
  • Isolate test data (separate dari production)
  • Document test data dependencies

5. ❌ Ignoring Performance Testing

Problem: Aplikasi mungkin functional tapi lambat.

Solution: Include performance testing:

  • Measure response times
  • Monitor resource usage
  • Test dengan realistic load
  • Identify bottlenecks early

Komunikasi Efektif dalam Testing

Cara Melaporkan Bug dengan Baik

Bug report yang baik memudahkan developer untuk fix:

  • ✅ Gunakan title yang descriptive dan specific
  • ✅ Sertakan steps to reproduce yang jelas
  • ✅ Jelaskan expected vs actual result
  • ✅ Lampirkan screenshot/video sebagai evidence
  • ✅ Tentukan severity dan priority dengan fair
  • ✅ Hindari technical jargon yang unclear

Kolaborasi dengan Developer

Testing bukan tanggung jawab QA saja:

  • 🤝 Involve developer dalam test planning
  • 🤝 Discuss edge cases bersama-sama
  • 🤝 Share test results dan insights
  • 🤝 Celebrate wins bersama

Continuous Learning dalam Testing

Dunia testing terus berkembang. Penting untuk selalu belajar:

Resources untuk Belajar

  • 📚 Books: "The Art of Software Testing", "Explore It!"
  • 🎓 Online Courses: ISTQB Certification, Udemy courses
  • 💬 Communities: QA communities, forums, local meetups
  • 📰 Articles & Blogs: Medium, Dev.to, Testing blogs
  • 🎬 YouTube Channels: Testing-focused channels

Skills untuk Develop

  • 💻 Programming skills untuk automation
  • 📊 SQL untuk database testing
  • 🌐 API testing dengan tools seperti Postman
  • 📱 Mobile testing expertise
  • 🔒 Security testing mindset
  • 📈 Performance & load testing

Kesimpulan

Testing adalah seni dan sains. Seni dalam memahami user perspective dan mindset, sains dalam mengaplikasikan systematic approach dan best practices.

Key takeaways:

  • ✅ Think like a user, not like a developer
  • ✅ Test early and often (shift-left approach)
  • ✅ Balance automation dan manual testing
  • ✅ Focus on risk and impact
  • ✅ Communicate effectively dengan team
  • ✅ Never stop learning dan improving
