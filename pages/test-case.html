Pengenalan

Halaman ini menampilkan contoh test cases yang telah saya buat serta implementasi Behavior-Driven Development (BDD) menggunakan Gherkin syntax. BDD adalah approach yang menggabungkan testing dengan dokumentasi yang lebih readable oleh non-technical stakeholders.

Test Case Format

Standar Test Case

Komponen Deskripsi Contoh
Test Case ID Identifikasi unik untuk test case TC-001
Test Title Deskripsi singkat tentang test User dapat login dengan kredensial yang valid
Precondition Kondisi awal sebelum test dijalankan User belum login, sudah di halaman login
Test Steps Langkah-langkah yang dilakukan 1. Masukkan email 2. Masukkan password 3. Klik login
Expected Result Hasil yang diharapkan User berhasil login dan diarahkan ke dashboard

Contoh Test Case 1: User Login

TC-001: Login dengan Kredensial Valid

Precondition User sudah terdaftar di sistem
Test Steps 1. Navigasi ke halaman login
2. Masukkan email: test@example.com
3. Masukkan password: password123
4. Klik tombol "Login"
Expected Result ✓ User berhasil login
✓ Halaman redirect ke dashboard
✓ Username ditampilkan di top right
✓ Token disimpan di localStorage

TC-002: Login dengan Kredensial Invalid

Precondition User sudah di halaman login
Test Steps 1. Navigasi ke halaman login
2. Masukkan email: test@example.com
3. Masukkan password: wrongpassword
4. Klik tombol "Login"
Expected Result ✓ Login gagal
✓ Pesan error ditampilkan: "Invalid credentials"
✓ User tetap di halaman login
✓ Token tidak dibuat

BDD dengan Gherkin Syntax

Behavior-Driven Development (BDD) menggunakan format Gherkin yang lebih mudah dipahami oleh semua pihak (developer, tester, business analyst).

Feature File: User Authentication

Feature: User Authentication
  As a user
  I want to login to the application
  So that I can access my personal dashboard

  Scenario: User logs in with valid credentials
    Given User is on the login page
    When User enters email "test@example.com"
    And User enters password "password123"
    And User clicks the login button
    Then User should be redirected to the dashboard
    And User should see "Welcome Back" message
    And User profile should be visible

  Scenario: User login fails with invalid password
    Given User is on the login page
    When User enters email "test@example.com"
    And User enters password "wrongpassword"
    And User clicks the login button
    Then User should see error message "Invalid credentials"
    And User should remain on the login page

  Scenario: User login fails with empty email
    Given User is on the login page
    When User leaves the email field empty
    And User enters password "password123"
    And User clicks the login button
    Then User should see validation error "Email is required"
    And The login button should be disabled

Feature File: Product Management

Feature: Product Management
  As a user
  I want to manage products
  So that I can keep my inventory updated

  Scenario: Add new product
    Given User is logged in
    And User is on the products page
    When User clicks "Add Product" button
    And User fills in the following product details:
      | Field       | Value                      |
      | Name        | New Test Product           |
      | Description | This is a test product     |
      | Price       | 99.99                      |
      | Category    | Electronics                |
    And User clicks the "Save" button
    Then Product should be created successfully
    And "New Test Product" should appear in the product list
    And Success message should display "Product added successfully"

  Scenario: Edit existing product
    Given User is logged in
    And Product "Laptop" exists in the system
    When User searches for "Laptop"
    And User clicks the edit icon
    And User changes price to "1299.99"
    And User clicks "Save"
    Then Product price should be updated
    And Updated timestamp should reflect the change

  Scenario: Delete product
    Given User is logged in
    And Product "Old Product" exists
    When User searches for "Old Product"
    And User clicks the delete icon
    And User confirms the deletion
    Then Product should be removed from the list
    And Deletion confirmation message should appear

Feature File: Search Functionality

Feature: Search Products
  Background:
    Given User is on the products page

  Scenario: Search with valid product name
    When User enters "Laptop" in the search field
    And User presses Enter
    Then Results should display products matching "Laptop"
    And Results count should be greater than 0

  Scenario: Search with no results
    When User enters "XYZ12345NonExistent" in the search field
    And User presses Enter
    Then "No products found" message should appear
    And Results list should be empty

  Scenario: Clear search results
    When User enters "Product" in the search field
    And User clicks the X button in search field
    Then Search field should be empty
    And All products should be displayed again

Implementation - Step Definitions (Cypress)

// features/step_definitions/login.js
import { Given, When, Then } from '@cucumber/cucumber';

Given('User is on the login page', () => {
  cy.visit('/login');
});

When('User enters email {string}', (email) => {
  cy.get('[name="email"]').type(email);
});

When('User enters password {string}', (password) => {
  cy.get('[name="password"]').type(password);
});

When('User clicks the login button', () => {
  cy.get('button[type="submit"]').click();
});

Then('User should be redirected to the dashboard', () => {
  cy.url().should('include', '/dashboard');
});

Then('User should see {string} message', (message) => {
  cy.contains(message).should('be.visible');
});

Best Practices untuk Test Cases

  • ✅ Clarity: Test case harus jelas dan mudah dipahami
  • ✅ Independence: Setiap test case berdiri sendiri, tidak bergantung pada test lain
  • ✅ Repeatability: Test harus menghasilkan hasil yang sama setiap kali dijalankan
  • ✅ Completeness: Test case harus mencakup semua scenarios penting
  • ✅ Positive & Negative: Test case harus mencakup happy path dan error cases
  • ✅ Edge Cases: Jangan lupa test boundary values dan edge cases
  • ✅ Maintainable: Test case harus mudah di-update saat ada perubahan

BDD Best Practices

  • ✅ Gunakan language yang business dapat pahami
  • ✅ Fokus pada behavior, bukan implementation detail
  • ✅ Gunakan concrete examples dengan data spesifik
  • ✅ Hindari technical jargon di feature files
  • ✅ Organize scenarios dengan Background dan multiple scenarios
  • ✅ Gunakan scenario outlines untuk data-driven testing
  • ✅ Keep step definitions simple dan reusable
